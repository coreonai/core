# Domain 래퍼 등가성 테스트 (workLLM)

## 배경: 왜 이 스킬이 존재하는가

커밋 `ad86e22` 이전, `FilteredDomain`이 `truncate_completion`을 내부 도메인에
위임하지 않아 trait 기본 구현(no-op)이 조용히 사용됐다. 그 결과:

- `--prompt-skip-list`를 쓰는 모든 hard-tail 실험이 completion truncation **off** 상태로 실행됨
- 베이스라인 과소 측정: 0.246 (실제 0.422)
- RL 보상이 평가기와 3배 어긋남
- 연구 결론 오염: 철회 2건("inverted-U 수확 최적화", "RL collapse"), 하향 수정 1건(hard tail +0.254 → +0.203)

Rust 컴파일러는 "기본 구현을 쓰겠다는 선택"과 "위임을 깜빡한 실수"를 구분하지
못한다. 이 스킬은 그 간극을 테스트로 메운다.

## 절대 규칙

Domain 래퍼 또는 Domain trait을 건드리는 작업을 완료하기 전에, 아래 절차를
**모두** 수행해야 한다. 하나라도 생략한 채 작업을 완료로 보고하지 않는다.

## 절차

### 1. 실제 trait 정의를 먼저 읽는다

추측하지 말 것. `trait Domain`이 정의된 파일을 열어 메서드 전체 목록을
확인한다. 특히 다음을 기록한다:

- 메서드 이름 전체 목록
- 각 메서드에 **기본 구현(default impl)이 있는지 여부** — 기본 구현이 있는
  메서드가 위임 누락 사고의 후보다

### 2. 위임 체크리스트를 작성한다

수정 대상 래퍼(예: `FilteredDomain`)의 `impl Domain for ...` 블록과 trait
메서드 목록을 대조해, 메서드마다 셋 중 하나로 분류한다:

| 분류 | 의미 | 조치 |
|------|------|------|
| 의도적 오버라이드 | 래퍼의 존재 이유인 로직 (예: prompts 필터링) | 주석으로 `// override: <이유>` 명시 |
| 명시적 위임 | `self.inner.method(...)` 호출 | 유지 |
| **누락** | impl 블록에 없음 → 기본 구현으로 폴백 중 | **즉시 위임 추가** |

체크리스트 결과를 사용자에게 보고한다. "누락 0건"을 확인하기 전에는 다음
단계로 넘어가지 않는다.

### 3. 등가성 테스트를 작성·갱신한다

`references/equivalence_harness.rs`의 템플릿을 실제 trait 시그니처에 맞게
적용한다. 핵심 속성 두 가지:

**속성 A — 항등 구성 등가성 (필수)**
빈 skip list로 만든 `FilteredDomain`은 내부 도메인과 **모든** 메서드에서
동일한 출력을 내야 한다. 이 테스트 하나가 `ad86e22` 버그를 첫 실행에서
잡았을 것이다.

**속성 B — 필터 외 불변성 (필수)**
skip list가 비어있지 않아도, 필터링과 무관한 메서드(`truncate_completion`,
`evaluate` 등)는 내부 도메인과 동일하게 동작해야 한다. 래퍼의 계약은
"필터링 외에는 내부와 100% 동일"이다.

테스트는 반드시 trait의 **모든 메서드**를 순회해야 한다. 일부 메서드만
검사하는 테스트는 이 스킬의 요구를 충족하지 않는다.

### 4. trait에 메서드를 추가하는 경우 (추가 규칙)

- **기본 구현을 넣지 않는 것을 기본값으로 한다.** 기본 구현이 없으면 모든
  구현체(래퍼 포함)에서 컴파일 에러가 나므로 위임 누락이 원천 차단된다.
- 기본 구현이 정말 필요하다면: `rg "impl.*Domain for"` 로 모든 구현체를
  찾아 래퍼마다 위임을 직접 추가하고, 등가성 하네스의 메서드 목록에도 새
  메서드를 추가한다.
- 등가성 하네스에 메서드를 추가하지 않고 trait 메서드를 추가하는 것은 금지.

### 5. 새 래퍼를 작성하는 경우 (추가 규칙)

- 수동 위임 대신 `delegate` 크레이트(또는 `ambassador`) 사용을 우선 검토
  한다. 오버라이드하는 메서드만 명시하고 나머지는 매크로로 일괄 위임.
- 새 래퍼도 즉시 등가성 하네스에 등록한다 (속성 A, B 모두).

### 6. 테스트를 실행하고 결과를 보고한다

```bash
cargo test --package <평가 파이프라인 크레이트> equivalence
```

통과를 확인한 후에만 작업을 완료로 보고한다. 실패 시 래퍼 코드를 고치되,
**테스트의 기대값을 래퍼의 현재 동작에 맞추는 방식으로 수정하지 않는다**
(그게 바로 버그를 정답으로 굳히는 길이다).

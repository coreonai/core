01The three studies

contamination

LiveCodeBench generalizes · RL ~2× SFT

Contest-date split. Both recipes lift post-cutoff (unseen): SFT 0.0413→0.0562 (+2.5σ), K=8 RL →0.1105 (+5.7σ) — 6/6 seeds, RL ~2× SFT with a near-pure post-cutoff signature. Real learning, not recall.
ceiling

BigCodeBench ceiling probed · 6-seed

Real-library tasks, Docker sandbox. At aggregate pass@1, K=8 RL lifts base Hard 0.146 → 0.181 (+0.035, ~2σ); SFT's +0.009 stays in noise. K8 > SFT only +0.99σ — a lean, not LCB's +4σ. pass@5 drops: self-improve sharpens.
RL variance

Harvest flips the mean — ceiling at K=16

Objective lever (GRPO) dead; harvest lever makes RL high-mean (0.538, +0.174 over SFT). Swept K=2..32 on transfer: log-linear to K=16, flat at 32.

02Two hard rules

F32 · long prompts

BF16 corrupts generation past ~500 tokens (token-doubling garbage). Short HumanEval/MBPP prompts never hit it; LCB/BigCodeBench do. Use --dtype f32 (the dumper default; 7B F32 = 28GB, fits a 40GB card).

aggregate · not greedy

Match the metric to where the training signal lives. SFT sharpens the sampling distribution — it lifts aggregate pass@1 / pass@k but can drop the single greedy mode. A greedy run made self-improve look like a loss; aggregate pass@1 showed generalization.

03Run it

Scorer env: scratch-7b-sft/tools/lcb-venv (torch-free codegen_metrics, datasets 2.x). Generate in Rust, score with the official harness:

# LiveCodeBench — export, then base + recipe at the correct metric
lcb-venv/bin/python scripts/phase22_bench/lcb_export_problems.py release_v5
bash scripts/phase22_bench/lcb_agg_verify.sh          # base + recipe, aggregate pass@1

# score any dumped [{question_id, code_list}], with a cutoff window
lcb-venv/bin/python scripts/phase22_bench/lcb_score.py \
  --gens <path.json> --release release_v5 --start-date 2024-09-01   # post-cutoff
